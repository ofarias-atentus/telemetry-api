# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Central ingestion API in Go (module `telemetry-api`) that stores device inventory and hardware telemetry (battery, temperature, voltage, CPU, RAM) from iOS and Android devices in PostgreSQL, with TimescaleDB optional. The README calls the built binary `atelemetry-mobile`.

`cmd/atelemetry-mobile/` (`package main`) is the CLI and holds only the CLI. `main.go` dispatches the subcommands (`serve`, `migrate status|up|baseline`, `help`) and maps errors to exit codes (0 ok, 1 schema version mismatch, 2 usage, config, connectivity or other operational error). `serve.go` loads the config, builds the logger and calls `slog.SetDefault`, creates the pgx pool, pings it with a 10s timeout, runs `migrate.CheckVersion`, and serves an `http.Server` whose `Handler` is `api.NewServer(pool, logger).Handler()` and whose `ErrorLog` is `slog.NewLogLogger`. `migrate.go` wires the `migrate` subcommands. The rest is in `internal/`:

- `internal/config`: `Config` types (including `Log LogConfig{Level slog.Level; Format string}`), `Load(envFile string)` (reads the optional `.env` file with godotenv, then the environment, and reports all validation errors together), `DatabaseConfig.ConnString()` (sslmode only, for `database/sql` in migrations), and `DatabaseConfig.BuildConnString()` (adds `pool_max_conns`/`pool_min_conns` for pgxpool). Tests use an unexported `fromEnv(lookup)` and `t.Setenv`.
- `internal/logging`: `New(w io.Writer, cfg config.LogConfig) *slog.Logger`, which builds the stdlib `log/slog` logger in text or JSON format at the configured level.
- `internal/migrate`: schema migrations with goose v3, embedded from `internal/migrate/migrations/*.sql` (`go:embed`). `LatestVersion` (currently 4) is the version this binary requires. `AppliedVersion`, `Status` and `CheckVersion` only read; `CheckVersion` is serve's startup gate. `Up` takes a Postgres advisory lock and refuses a database that has legacy tables but no `goose_db_version`. `Baseline` detects the version (1-4) from the catalog and writes rows 0..N in one transaction. `owner.go` (`alignVersionsOwner`) sets `goose_db_version` to the owner of `devices`; `Up` and `Baseline` both call it. `Open` pins `search_path=public`. History table: `goose_db_version`.
- `internal/api`: the `DB` interface (`Exec` and `CopyFrom`, which `*pgxpool.Pool` satisfies), `Server`/`NewServer(db DB, logger *slog.Logger)` (a nil logger falls back to `slog.Default()`), and `Routes()`, which returns a dedicated `ServeMux`. `(*Server).Handler()` wraps that mux with the access-log and request-ID middleware in `middleware.go`. Handlers are in `devices.go` and `telemetry.go`, models in `models.go`.

It uses stdlib `net/http` with no router. The direct dependencies are `github.com/jackc/pgx/v5` (`pgxpool`, `CopyFrom`), `github.com/joho/godotenv` (`.env` loading) and `github.com/pressly/goose/v3` (migrations). Logging uses stdlib `log/slog` and adds no dependency.

New code goes in `internal/` packages. `cmd/atelemetry-mobile` only holds the CLI, and the build is `go build -o atelemetry-mobile ./cmd/atelemetry-mobile`. The `DB` interface is the test seam: handler tests inject a fake instead of a real pool.

The schema is defined by the migrations in `internal/migrate/migrations/`. The resulting shape: `countries` (PK `code CHAR(2)`, ISO 3166-1 alpha-2, with Spanish `name` and lowercase `aliases`), `hosts` (PK `host_pc`, one row per monitoring PC), `devices` (PK `device_id`, `country CHAR(2)` FK to `countries`, `host_pc` FK to `hosts`, core columns plus `attributes JSONB`), and `device_telemetry` (columns `time`, `device_id`, and `data JSONB` for metrics; FK to `devices`, and a hypertable on `time` when TimescaleDB is available).

Go style and practice guides are in `.claude/skills/golang-*` (from samber/cc-skills-golang) and apply to `.go` files.

## Language

The README, log messages, and error messages are in Spanish. Keep new messages and docs consistent with that. Log attribute keys (`request_id`, `device_id`, `status`) are English. This file is in English.

The capitalized Spanish startup error strings in `cmd/atelemetry-mobile/serve.go` (config read, pgx pool creation, ping) are user-facing messages kept byte-identical and logged at ERROR, so linters' error-string rules (lowercase, no capital) do not apply. Do not lowercase them. `migrate.go` reuses the config one ("Error crítico al leer la configuración de la API").

## Runtime behavior

- Configuration comes from environment variables, optionally loaded from `.env` in the current working directory, so run the binary from the repo root. `.env` holds real database credentials and is not tracked by git. Don't echo, read out, or copy its contents. Variables already set in the process environment win over `.env`; an exported empty value counts as unset. Required: `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`. Defaults: `SERVER_PORT` 8080, `DB_PORT` 5432, `DB_SSLMODE` disable, `DB_MAX_CONNS` 25, `DB_MIN_CONNS` 5, `LOG_LEVEL` info, `LOG_FORMAT` text. Validation: ports 1–65535, `DB_MAX_CONNS` >= 1, 0 <= `DB_MIN_CONNS` <= `DB_MAX_CONNS`, `LOG_LEVEL` one of debug|info|warn|error (case-insensitive), and `LOG_FORMAT` one of text|json (case-insensitive). `.env.example` is the committed template. `deploy/.env.docker.example` is the template for compose and `docker run --env-file`. Single quotes around values with `$`, `#` or spaces apply only to Compose `env_file` and godotenv `.env`; `docker run --env-file` does not strip quotes, so write those values unquoted there.
- The old `config.json` is still in git history with real database credentials, so the DB password should be rotated. Don't put the password in docs or output.
- CLI: no arguments prints usage to stderr and exits 2. `help`, `-h`, `-help` and `--help` print usage to stdout and exit 0. `migrate` requires exactly one action (`status`, `up` or `baseline`). `migrate status` prints to stdout.
- `serve` never migrates. It loads the config, builds the logger, creates the pgx pool, pings the database (10s timeout), and runs `migrate.CheckVersion`: the applied goose version must equal `LatestVersion`, otherwise it exits 1 and points to `migrate status`/`up`/`baseline`. It then logs `msg="API Ingestora central escuchando" addr=<host>:<port>` at INFO. `serve --host` defaults to all interfaces, `serve --port` defaults to `SERVER_PORT` (0 means use `SERVER_PORT`, otherwise 1–65535). There is no auth and no TLS.
- Exit codes: `main()` logs the returned error as one slog ERROR line (newlines replaced with `; `). Exit 1 for `migrate.ErrVersionMismatch` and `migrate.ErrNotVersioned` (schema behind, ahead or unversioned, or `baseline` refused because history exists). Exit 2 for everything else (usage, config, connectivity, permission, other operational errors). Config errors are all joined with `"; "` in one ERROR line and logged through slog's default handler before the logger exists, so they ignore `LOG_FORMAT`/`LOG_LEVEL`. `migrate` never sets the configured logger as default, so its errors also use the default handler.
- HTTP limits (`newHTTPServer`): `ReadHeaderTimeout` 10s, `ReadTimeout` 30s, `WriteTimeout` 30s, `IdleTimeout` 120s, `MaxHeaderBytes` 64 KiB. On SIGINT or SIGTERM, `serveLifetime` logs `señal de apagado recibida`, calls `Shutdown` with a 15s budget, falls back to `Close` if that fails, and closes the pool last.
- Logs go to stderr through `log/slog`, in text or JSON format per `LOG_FORMAT`. Every request logs one `msg="solicitud"` line with `request_id`, `method`, `path`, `status`, `bytes`, `duration_ms`, and `remote_addr`. Level is INFO for status < 400, WARN for 4xx, ERROR for 5xx. A handler panic logs that line at ERROR with status 500 and a `panic` attr (even if headers were already sent), then `net/http` handles the panic as before. An `http.ErrAbortHandler` abort is also logged at ERROR with status 500, but without the `panic` attr. Errors from `http.Server` go through `slog` at ERROR via `ErrorLog`.
- Request IDs: an incoming `X-Request-ID` is kept if it is 1–64 chars of `[A-Za-z0-9._-]`; otherwise a 16-hex-char ID is generated. The ID is returned in the `X-Request-ID` response header and set as `request_id` on every log line for that request, including handler errors.
- DB calls in handlers still use `context.Background()`; only logging uses `r.Context()`. Known gap: no per-query timeouts.
- `POST /api/v1/devices` takes a JSON array of `DeviceInventory`. `host_name`, `host_ip`, and `host_location` stay top-level in both formats. Each device is one SQL statement (a CTE upserts `hosts`, then `devices`, `ON CONFLICT ... DO UPDATE`), with no transaction across devices, so valid devices are stored even when others fail. `platform` is never updated. `host_ip` is overwritten by the latest device, and `host_location` is kept when a device sends nil or empty. Stored `model` and `battery_design_cap` are preserved when already present.
- `POST /api/v1/devices` response: all devices stored (or an empty array) returns 200 `{"status":"success"}`, with no explicit Content-Type. Any failure returns `{"status":"error","stored":N,"failed":[{"device_id":"X","error":"..."}]}` with `Content-Type: application/json`, entries in request order (`deviceErrorResponse` in `internal/api/devices.go`). The status is 422 when every failure is a data error (SQLSTATE class 22 or 23, except 23505), and 500 otherwise: non-Postgres errors, other SQLSTATEs, 23505 (only a concurrent-insert race, worth retrying), or a mix of data and non-data failures. Reasons (`deviceFailureReason`): `país desconocido` (23502 on `country`), `valor demasiado largo` (22001), `datos inválidos` (other 22/23), `error interno` (anything else). Logs: each failed device is `upsert falló` (attrs `device_id`, `err`) at WARN for data errors and ERROR otherwise; the request also logs one `dispositivos rechazados` line (attrs `stored`, `failed`) at WARN for 422 or ERROR for 500. The device agent treats any 2xx as registered and then sends that device's telemetry, so a non-2xx keeps it from sending telemetry for devices that were not stored.
- Two device formats, which can be mixed. Legacy: `alias_name`, `model`, `os_version`, `battery_design_cap` at top level; unsent ones are stored as `""` or 0. New: `attributes` object with any keys; legacy fields that were sent are merged in only when their key is absent, so `attributes` wins. A non-object `attributes` gets 400. The logic is `DeviceInventory.attributes()` and `hostLocation()` in `internal/api/models.go`.
- `country` accepts an ISO code or a name/alias from `countries`, trimmed and case-insensitive (`'Chile'`, `' cl '`, `'Perú'`, `'peru'` all resolve). `handleDevices` lowercases it in Go before the SQL, because Postgres `lower()` only folds ASCII under a C locale. The SQL resolves it with a scalar subquery. An unknown value makes that device's statement fail with a NOT NULL error (23502 on `country`): the device and its host upsert are skipped, the device is listed in `failed` as `país desconocido`, it is logged as `upsert falló` at WARN, and the response is 422. An existing device sent with an unknown country is not updated and gets the same 422.
- Known follow-ups, not fixed: a device that moves to another host leaves the old `hosts` row orphaned; a device sending an empty `host_ip` blanks the IP of its host for all its devices.
- `POST /api/v1/telemetry` takes a JSON array of `TelemetryData`, written with one `CopyFrom` call into `device_telemetry` (columns `time`, `device_id`, `data`), so the batch is all-or-nothing. Each row's `data` comes from `TelemetryData.payload()` in `internal/api/models.go`. An unknown `device_id` violates the FK and fails the whole batch with 500, logged as `inserción masiva CopyFrom fallida` (attrs `records`, `err`). An empty array returns 200 with no body. Success returns 201 `{"status":"created","records":N}`. A zero `time` is replaced with `time.Now()`.
- Two input formats, which can be mixed in one batch. Legacy: metric fields at the top level, no `data` (or `"data": null`); all 8 legacy keys are stored in `data`, unsent ones as 0/false. New: `data` is an object with any keys, nested values allowed. Legacy fields that were sent are merged in only when their key is absent from `data`, so `data` wins. A `data` that is not an object gets 400 with the decoder's message. Numbers are no longer range-checked by `NUMERIC` columns.
- Non-POST requests get 405. Malformed JSON gets 400, including a single object sent instead of an array.
- The JSON field `host_name` is stored in the `host_pc` column.
- `README.md` documents the endpoints, the CLI, Docker and deployment; keep it in sync when handler behavior or commands change.

## Database

- Requires PostgreSQL 14+. TimescaleDB is optional: migration `00001` runs `CREATE EXTENSION timescaledb` and `create_hypertable` only if `timescaledb` appears in `pg_available_extensions`. The app uses no TimescaleDB functions. This is how it has been run locally (PostgreSQL 16 without TimescaleDB).
- Fresh install: `atelemetry-mobile migrate up` on an empty database. There is no `database.sql` anymore.
- Migrations are goose SQL files in `internal/migrate/migrations/`, embedded in the binary: `00001_initial` (original schema), `00002_device_telemetry_jsonb` (moves the 8 metric columns into `data`), `00003_devices_attributes_jsonb` (creates `hosts`, moves `host_ip` and `host_location` there, moves the 4 attribute fields into `devices.attributes`, adds the FK), and `00004_countries` (creates `countries`, maps `devices.country` to ISO codes, changes it to `CHAR(2)` with the FK; it fails and lists the values if any existing value cannot be mapped). Every migration is irreversible (no `-- +goose Down`) and runs in a transaction. `00002`–`00004` set `SET LOCAL lock_timeout = '5s'`; `00001` does not. Before changing anything, `00002`–`00004` check the role (must own the table, or be superuser), missing or already-present columns, and dependent views/matviews/rules, and stop with a Spanish error. `00002` also stops on compressed or compression-enabled hypertables and on continuous aggregates (the error includes the decompress commands). `00003` stops on NULL `host_pc` or over-long values (`host_pc` > 100 and `host_ip` > 15 on the IP winner per host, `host_location` > 50 on the location winner per host). `00004` stops on unmappable `devices.country` values and lists them with counts. Before each destructive step they verify their own result (row counts, per-metric or per-attribute key counts, every device has a host and a country) and roll back on mismatch.
- Every schema change is a new numbered file in `internal/migrate/migrations/` plus a bump of `LatestVersion` in `internal/migrate/migrate.go`. `migrate_test.go` checks that the numbering is contiguous from 1 and that the highest version equals `LatestVersion`.
- `migrate up` takes the advisory lock `gooseLockKey` (goose's session locker) and refuses a database that has any of `countries`, `device_telemetry`, `devices`, `hosts` but no `goose_db_version` (exit 1, message points to `baseline`). That check runs before goose takes the lock, so run `up` from one place at a time. A migration failure makes `up` exit 2; the failed migration is rolled back completely and earlier ones stay applied, so fix the cause and rerun `up`.
- Ownership: `hosts`, `countries` and `goose_db_version` end up owned by the owner of `devices`, so migrating as superuser `postgres` leaves app tables owned by the app role. Fresh installs keep the owner of whoever ran them. `up` repairs `goose_db_version`'s owner on an already-migrated database.
- `00003` builds `hosts` per `host_pc`: `host_ip` comes from the latest device (`updated_at DESC NULLS LAST`, ties by smallest `device_id`). `host_location` comes from the latest device whose `host_location` is non-empty (same ordering; `''` counts as empty, no trimming, same as the API's `hostLocation()`), and is NULL only if no device of that host has one.
- `migrate baseline` is for databases created by the old psql scripts (`database.sql` plus `migrations/001`–`003`). `detectVersion` in `baseline.go` maps the catalog to version 1–4, and the command writes `goose_db_version` rows 0..N in one transaction. It refuses if `goose_db_version` exists (exit 1), if the database is empty, or if the schema matches no known version (exit 2), and it changes nothing else. Then run `migrate up` for the rest.
- The upsert SQL (`upsertDeviceQuery` in `internal/api/devices.go`) is pinned by `TestUpsertDeviceQueryText`. Changing its columns, conflict clause, or SET list fails that test, so update both together.
- The `countries` seed lives only in `00004_countries.sql`. `schema_test.go` reads that file. It checks the exact 249 ISO codes and unique names, fails if any code, name, or alias resolves to two countries, and checks that the country matching predicate in the upsert matches the one in `00004` (two occurrences there: DO block and UPDATE). Edit the seed in that file only.
- Deploy ordering: stop the API and deploy the new binary together with the migration. The old binary inserts into dropped columns and the new one needs the new columns, so neither works against the other schema. `00003` and `00004` stall telemetry ingestion until COMMIT (`00004` because `ALTER TYPE` rewrites `devices`). Dependent views block their `DROP COLUMN` or `ALTER TYPE`. Check TimescaleDB compression and continuous aggregates before running any migration. Back up with `pg_dump` first; there are no reverse migrations.
- Existing deployments: stop the API, back up, deploy the new binary, run `migrate baseline` once only for databases created by the old scripts, then `migrate up`, then start `serve`.

## Commands

```bash
go mod download
cp .env.example .env                                      # then edit; .env is gitignored
go build -o atelemetry-mobile ./cmd/atelemetry-mobile     # or: go run ./cmd/atelemetry-mobile serve
./atelemetry-mobile serve                                 # from the repo root, reads .env; never migrates
./atelemetry-mobile serve --host 127.0.0.1 --port 9090
LOG_LEVEL=debug LOG_FORMAT=json ./atelemetry-mobile serve   # override logging for one run
./atelemetry-mobile migrate status                        # exit 0 only when up to date
./atelemetry-mobile migrate up                            # empty database, or pending migrations
./atelemetry-mobile migrate baseline                      # once, for databases created by the old psql scripts
go vet ./...
gofmt -l .
go test ./...
go test -race ./...
go test -run TestHandleDevices ./internal/api/    # single test
TEST_DATABASE_URL='postgres://user:pass@host:5432/attelemetry?sslmode=disable' \
  go test -tags integration -run Integration ./internal/api/   # database already at version 4 (migrate up)
TEST_MIGRATE_DATABASE_URL='postgres://user:pass@host:5432/scratch?sslmode=disable' \
  go test -tags integration -run Integration ./internal/migrate/   # EMPTY throwaway database, no pool_* params; does not clean up
docker build -t atelemetry-mobile .
docker run --rm --env-file .env.docker atelemetry-mobile migrate status
docker run -d --name atelemetry-mobile --env-file .env.docker -p 8080:8080 --stop-timeout 30 atelemetry-mobile
```

Unit tests use stdlib `testing` and `httptest` with a fake DB (`internal/api/fake_db_test.go`) and need no database. `schema_test.go` reads the countries migration and checks the predicate against the upsert, so it also needs no database. The API integration test (`internal/api/integration_test.go`, build tag `integration`) skips when `TEST_DATABASE_URL` is unset, assumes the database is migrated to version 4, and creates and deletes its own `itest-*` rows. The migrate integration test (`internal/migrate/integration_test.go`, build tag `integration`) skips when `TEST_MIGRATE_DATABASE_URL` is unset, and needs an empty throwaway database. `internal/migrate/integration_upgrade_test.go` (`TestMigrateUpgradeLegacyDataIntegration`, same env var, same build tag) runs `DROP SCHEMA public CASCADE` before building the legacy schema with data, so it is for throwaway databases only.

Docker: the `Dockerfile` is two stages (`golang:1.27.1-bookworm` build with `GOTOOLCHAIN=local` and `CGO_ENABLED=0`; runtime `gcr.io/distroless/static-debian12:nonroot`, `ENTRYPOINT ["atelemetry-mobile"]`, `CMD ["serve"]`). `.dockerignore` is an allowlist (`go.mod`, `go.sum`, `cmd/`, `internal/`): keep it that way so `.env` never enters the image. Runtime config comes from `--env-file` or compose `env_file`; quote values with `$`, `#` or spaces only for `env_file` (see Runtime behavior). `deploy/docker-compose.yml` is the reference compose file, and `installer/` builds an Ubuntu 20.04 `.deb` that installs it under `/srv/atelemetry-mobile` with the systemd unit `atelemetry-mobile.service` (`docker compose up`). The image name `atentuschile/atelemetry-mobile` used in compose is an assumption to confirm.

There is no Makefile or linter config.

```bash
curl -i http://localhost:8080/api/v1/devices                                                       # expect 405
```
